V-iter17: 引入 efc_force 真实力反馈 + Y 轴随机扩大
===================================================================
日期: 2026-04-05
基础: 从 V-iter16 resume 最佳 checkpoint (000015728640, reward=335.9)

▶ 改动摘要:

1. 【核心】efc_force 真实接触力提取
   - 问题: MJX (及原生 MuJoCo) 的 touch sensor 因 site cutoff=0.8mm 过小，
     永远返回全零。之前所有力反馈奖励 (stable_hold, force_contact) 被迫禁用。
   - 发现: data.contact.geom + data.contact.efc_address + data.efc_force 可以
     正确提取每个 geom pair 的法向约束力，在 MJX JIT 中完全可用。
   - 实现: 新增 _get_contact_forces_efc() 方法，遍历 contact slots:
     * 找到 dist < 0 的活跃接触
     * 匹配 (fingertip_geom, cube_geom) 对
     * 读取 efc_force[efc_address] 获取法向力
     * 按指尖聚合，返回 5 维力向量 [index, middle, ring, pinky, thumb]
   - 验证: 闭合测试中 index=0.55N, thumb=0.05N，force_contact 奖励=0.17

2. 【观测】触觉输入由 touch sensor 改为 efc force
   - 旧: 读取 80 路 touch sensor (全零) → pooling → 5 维 (全零)
   - 新: 直接使用 EMA 平滑后的 efc force (5维) + 观测噪声
   - 维度不变 (5)，checkpoint 兼容

3. 【奖励】启用两个力反馈奖励通道
   - stable_hold: 0 → 5.0
     含义: contact_signal(总力>0.5时饱和) × lin_stable(低线速度) × ang_stable(低角速度)
     作用: 奖励"有接触且方块不动"，直接衡量抓握稳定性
   - force_contact: 0 → 2.0
     含义: 每指力在 [0.08, 1.2]N 区间线性映射到 [0,1]，取5指均值
     作用: 鼓励多指同时接触受力，防止单指依赖

4. 【环境】方块 Y 轴随机范围扩大
   - 旧: cube_jitter = [0.003, 0.003, 0.002]  (Y: ±3mm)
   - 新: cube_jitter = [0.005, 0.008, 0.003]  (Y: ±8mm)
   - 理由: 增强抓取对侧向偏移的鲁棒性

5. 【不变】所有已有奖励权重保持与 V-iter16 完全一致
   - hold_position=120, contact=5, thumb_engage=8, closure=5, distal_closure=5,
     human_pose=5, drop_risk=-25, survival=0.5, termination=-80
   - 避免 V-iter14 教训 (多权重同时变化→value function mismatch→退化)

▶ 训练配置:
   - 从: V-iter16 resume checkpoint 000015728640 (reward=335.9)
   - num_envs: 4096
   - total_steps: 200M
   - lr: 2e-4
   - num_evals: 40
   - camera: palm
   - suffix: v_R17_efc_force

▶ 预期效果:
   - 力反馈提供接触质量信号 → 鼓励多指同时夹持
   - stable_hold 奖励低速度 → 减少支撑释放后方块震荡跌落
   - Y jitter 扩大 → 更鲁棒的位置泛化

▶ 实际结果: ❌ 失败 — 奖励持续退化
   - 训练曲线: 230.6(0M) → 213.1(5.2M) → 184.7(10.5M) → 182.9(15.7M) → 134.7(21M)
   - 力奖励在增长 (fc: 6.5→8.9, sh: 4.2→6.6)，但主要奖励大幅下降
   - 在 21M 步时提前终止

▶ 教训:
   1.【观测兼容性】将触觉 obs 从零改为 efc 力 → normalizer 失配 →
     策略输出全乱 → reward=6。必须保持 obs 为零，力只用于奖励。
     (已在训练前修复，obs 保持为零)
   2.【多变量同时更改】同时引入 stable_hold=5.0 + force_contact=2.0 +
     Y jitter 3倍扩大(±3mm→±8mm) → 无法区分哪个因素导致退化。
   3.【Y jitter 过大】16mm 总范围相对 30mm 方块和手指工作空间过大，
     导致许多初始位置难以抓取，init eval 就从 335→230 (-30%)。
   4.【stable_hold 与 lifting 可能冲突】奖励低速度，但 lifting 需要速度，
     形成梯度冲突（待进一步验证）。

V-iter18: 保守力反馈 — 仅 force_contact=1.0 + 适度 jitter
===================================================================
日期: 2026-04-05
基础: 从 V-iter16 resume 最佳 checkpoint (000015728640, reward=335.9)

▶ 改动摘要 (相对 V-iter16):

1. 【力反馈】force_contact: 0 → 1.0（轻柔正反馈）
   - V-iter17 用了 2.0，这次减半
   - 仍使用 efc_force 提取真实接触力（obs 保持零）
   - 含义: 每指力在 [0.08, 1.2]N 线性映射，5指均值

2. 【禁用】stable_hold: 保持 0.0
   - V-iter17 的 5.0 可能造成梯度冲突
   - 先单独测试 force_contact 效果

3. 【环境】适度 Y jitter 扩大
   - V-iter16: [0.003, 0.003, 0.002] (Y: ±3mm)
   - V-iter18: [0.004, 0.005, 0.003] (Y: ±5mm) — 适度扩大
   - V-iter17 的 ±8mm 明显过大

4. 【不变】所有已有奖励权重与 V-iter16 完全一致

▶ 原则: 一次只改一个主要变量 (force_contact=1.0)，jitter 只适度增大

▶ 训练配置:
   - 从: V-iter16 resume checkpoint 000015728640 (reward=335.9)
   - suffix: v_R18_force_contact_only
   - 其余同 V-iter17

▶ 实际结果: ✅ 重大突破！ — 峰值 reward=1142.8
   训练曲线 (19 evals, 94.4M步):
     0M: 130.6 → 155.9 → 126.2 → 338.7 → 454.1 → 288.7 → 257.2 →
     477.3 → 403.8 → 807.0 → 1078.8 → 1142.8(峰值@68.2M) →
     275.5 → 143.6 → 254.1 → 134.4 → 177.3 → 169.4 → 213.8
   - 力反馈确认有效: force_contact 2.3→13.1 持续增长
   - Episode length: 峰值 248 步（满分500），方块持住近一半时间
   - 问题: lr=2e-4 在 fine-tuning 场景下偏高，过了峰值后 policy drift 崩盘
   - 被 V-iter19 替代（降低 lr 从峰值 checkpoint 续训）

▶ 教训:
   1. force_contact=1.0 是正确权重 — 产生了 3× 历史最佳的突破
   2. lr=2e-4 对 fine-tuning 过高，导致过优化后崩盘
   3. 峰值 checkpoint 可恢复: 68.2M 步处 000068157440

V-iter19: 低学习率稳定训练 — lr=1e-4 从 V-iter18 最佳续训
===================================================================
日期: 2026-04-05
基础: V-iter18 最佳 checkpoint (000068157440, reward=1142.8)

▶ 改动摘要: 仅降低学习率
   - lr: 2e-4 → 1e-4（防止过优化 drift）
   - 其余配置与 V-iter18 完全一致

▶ 实际结果: ✅ 稳定高性能
   训练曲线 (14 evals, 68.2M步):
     0M: 1033.2 → 1106.5 → 1003.8 → 1013.1 → 874.1 → 1107.7(最佳@26.2M) →
     1062.0 → 887.0 → 994.5 → 774.1 → 1046.0 → 762.5 → 907.1 → 1014.4
   - 均值 ≈ 988，范围 762-1108
   - 相比 V-iter18 (range 130-1143): **方差显著降低**
   - 26.2M 步后开始缓慢下降，说明 lr=1e-4 在后期仍偏高
   - 最佳 checkpoint: 000026214400 (reward=1107.7)

▶ 教训:
   1. lr=1e-4 >> lr=2e-4 用于 fine-tuning 稳定性
   2. 峰值出现在 ~26M 步，之后 value function estimation 开始漂移
   3. 下一步: 更低 lr (5e-5) 以延长稳定期

V-iter20: stable_hold=2.0 一决胜负测试
===================================================================
日期: 2026-04-05
基础: V-iter19 最佳 checkpoint (000026214400, reward=1107.7)

▶ 改动: stable_hold: 0 → 2.0
   - V-iter17 用 5.0 和 force_contact=2.0 同时,无法区分是谁惩罚
   - 此次仅改 stable_hold，隔离该变量

▶ 实际结果: ❌ 确认 stable_hold 与任务根本冲突
   训练曲线 (5 evals, 21M步):
     0M: 1036.2 → 318.3 → 163.1 → 257.2 → 185.9
   - 同一个 checkpoint, V-iter19(sh=0): ~1000, V-iter20(sh=2.0): ~200
   - 原因: stable_hold 奖励"低线速度+低角速度"，但 holding 需要方块微动来维持
     动态平衡。stable_hold 让手指变得僵硬，反而更容易丢方块。

▶ 教训: 【永久禁用 stable_hold】— 该奖励与竖直抓取任务根本不兼容。
