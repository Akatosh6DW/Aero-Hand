## R06: 重大改进 (当前)
**时间**: 2026-04-11 13:xx  
**配置**: 40M steps, lr=3e-4, 4096 envs, **从零训练**  
**改动依据**: 对比 V1(EpLen=493) vs V2(EpLen=105) 发现3个关键差异

### 改动1: 支撑台瞬间释放 (最关键)
```
release_after_sec: 4.0 → 3.0  (提前1s释放)
release_ramp_sec:  1.5 → 0.0  (瞬间释放，不再渐退)
```
**理由**: V1 使用 ramp=0 的瞬间释放，EpLen=493。V2 的 1.5s 渐退导致 released_gate 在 80-110 步间只有 0~100% 的梯度信号，策略无法得到明确的"必须独立抓住"压力。EpLen=105 恰好等于渐退完成点。

### 改动2: 观测空间扩展 (17D → 23D)
```python
# 旧 state (17D):
state = [motor_targets(6), tactile(5), last_action(6)]

# 新 state (23D):
state = [motor_targets(6), tactile(5), last_action(6),
         cube_pos_error(3),    # palm-cube 位置差
         cube_vel_scaled(3)]   # 方块速度/0.15 归一化
```
**理由**: V2 直接关节控制不像 V1 腱绳有机械冗余自动补偿。策略需要显式知道方块在哪、在往哪移动，才能做出反应性调整。这是从"盲抓"到"视觉反馈抓"的关键升级。

### 改动3: 奖励函数重设计

### 预期效果

## 环境修复 (R14 ~ R15 之间)

### 修复1: Palm Mesh 碰撞 (关键)
`right_hand_v2_vertical.xml` 中 `<mesh file="base_link.STL"/>` 被 menagerie assets dict 中同名的 V1 mesh (1.3MB, 13180 verts) 覆盖，导致掌部在 RL 仿真中使用了错误的 V1 几何。
- **修复**: 创建符号链接 `v2_base_link.STL` → `base_link.STL`，XML 引用改为 `v2_base_link.STL`
- **影响**: 正确的 V2 掌部 (2.6MB, 25947 verts) 物理特性不同，策略需要重新适应

### 修复2: 移除多余桥接几何体
移除 `palm_bridge_plate` geom (0.025m 圆柱体)，该几何体是旧版遗留，影响碰撞。

### 修复3: 摄像机角度
更新 `scene_mjx_grasp_v2.xml` 中的 side 和 palm 摄像机位置，确保完整展示手的画面。

### R48: 全奖励门控 — 彻底消除支撑期免费奖励

**配置**: 20M steps, **lr=2e-4**, **4096 envs**, 从**R41 checkpoint**继续
**核心改动**: 所有正向奖励×released_gate, 恢复2+2s支撑

#### 设计理念
R38-R47共同发现: 无论奖励怎么调, **支撑期间的免费奖励** 总是主导梯度。
- 1+1s支撑: EL≈40 (释放点=step 40)
- 2+2s支撑: EL≈80 (释放点=step 80)
策略总是学到"骑支撑台", 因为支撑期间approach/closure/contact等几乎不需要主动gripforce就能获得。

**解法**: 支撑期间**所有正奖励=0**。只有released_gate>0时（支撑开始释放后）才有奖励。
这迫使策略: 即使知道怎么approach+close（Phase 1已学会），也必须学会**在支撑释放时/后维持**才能获得奖励。

#### 具体改动 (R47→R48)
| 项目 | R47 | R48 | 理由 |
|------|-----|-----|------|
| **门控范围** | 仅force类奖励 | **全部11个正奖励** | 消除免费奖励 |

## C32: MJX扰动力数值稳定性修复 (2026-04-22)

### 背景
- 用户基于 C30 视频的逐帧诊断指出: `step 282 (~14.10s)` 出现 `qpos/qvel` 全量 NaN, 手掌因是固定基座仍可见, 手指与方块因依赖 `qpos` 渲染而瞬间消失。
- 该现象属于 **MJX 物理积分阶段的数值爆炸**, 不是显示 bug。
- 高风险触发链路是: `external_force + gravity_tilt + orientation_flip` 在支撑释放后叠加, 导致施加到方块 freejoint 的合力过大。
