【iter9 设计思路】
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

  核心改动（2 项）：
    1. gamma 0.99 → 0.995（延长规划视野：100步→200步，覆盖半个 episode）
       理由：iter4 的 gamma 0.97→0.99 是最大单次突破（+35步），继续提高有望打破平台
    2. 新增 soft_contact=5.0（安全力区间 bell-shaped 正反馈）
       理由：在 [0.1N, 2.5N] 区间内持续给予奖励，避免 agent 因
             force_overload 惩罚而不敢施力，同时限制过大力

  配套改动：
    - 回退 iter7 的权重变更（hold=150, stable=15, balance=1.5, survival=2.0）
    - 改进 _cost_force_overload：quadratic + cubic 非线性惩罚（渐进式更强）
    - LR=3e-5, 40M步, 从 iter5 best checkpoint 恢复

  新增代码：
    _reward_soft_contact(): bell-shaped 安全接触奖励
      lower_gate = sigmoid(20*(|f| - F_min))  -- 左侧上升
      upper_gate = sigmoid(10*(F_max - |f|))  -- 右侧下降
      reward = mean(lower_gate * upper_gate)

    _cost_force_overload()（升级版）:
      overload = max(|f| - 2.8N, 0)
      cost = overload^2 + (overload/0.5)^3
      轻微超载温和惩罚，严重超载陡峭惩罚

【RMA 师生蒸馏架构设计（Sim2Real 储备）】
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

  代码位置：sim_rl/rma_reference.py（PyTorch 参考实现）

  架构概述：
    Teacher Encoder:  精确力(15D) → MLP(128,64) → z_t(8D)
    Student Adapter:  历史序列(50帧×17D) → TCN(32,64,64) → 池化 → z_hat(8D)
    Base Policy:      (proprio(17D) + z_t(8D)) → MLP(512,256,128) → action(6D)
    蒸馏损失:         L = MSE(z_hat, z_t.detach())

  参数量：214K total (Encoder 10.8K, Adapter 24.9K, Policy 178K)

  训练流程：
    Phase 1: 冻结 Adapter，用精确力 + PPO 训练 Encoder + Policy
    Phase 2: 冻结 Policy + Encoder，用蒸馏 MSE 训练 Adapter
    Phase 3 (可选): 端到端微调

【关键教训总结】
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

  1. 同时修改多个奖励权重 → value function mismatch → 需大量步数恢复
  2. gamma 提升是突破平台期最有效手段（iter4: +35步）
  3. unroll_length 增加到 60 无效且可能有害（iter6 退化）
  4. 方案A（纯提高奖励权重）在 ~493 平台期完全失效
  5. 需保持 checkpoint 与奖励权重的一致性（从同一权重下的 ckpt 恢复）
